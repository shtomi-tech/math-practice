# 数学問題の作問原則

`math-practice` でオリジナル問題を作成・採用するときの基準。大学受験向けの演習問題とミニ試験の双方に適用する。

## 1. 作問の基本方針

### 1.1 数値より先に、測る力を決める

問題を作る前に、次の一文を完成させる。

> この問題は、＿＿＿＿できるかを確認する。

「二次関数を出題する」「場合の数を出題する」だけでは不十分。例えば、次のように観察できる行動まで具体化する。

- 定義域の端点を含めて最大・最小を判定できる
- 必要条件と十分条件を区別し、反例を挙げられる
- 場合分けの重複・漏れを確認しながら数えられる
- 式・表・グラフを相互に読み替えられる

### 1.2 問題の役割を先に分類する

一問にすべてを詰め込まない。主な役割を一つ決める。

- **基礎確認**：一つの知識・手続きを正確に使う
- **診断**：典型的な誤りや未理解を見つける
- **接続**：複数の表現や概念を結び付ける
- **転移・発展**：解法を選び、条件を整理し、説明する
- **試験**：限られた時間内で複数の力を測る

## 2. 難易度と認知的要求

難しさは計算量だけで決めない。次の四段階を意識する。

1. 知識・公式を再生する
2. 手順をそのまま適用する
3. 表現や概念を関連付けて手順を選ぶ
4. 方針を自分で決め、探究・説明する

難易度を調整するときは、次の要素を分けて変更する。

- 必要な既習事項
- 解法選択の幅
- 場合分け・判断の数
- 式・表・グラフ・図の変換
- 計算の長さ
- 文章の読解量
- 条件の見つけやすさ
- 制限時間

同じ解法を反復して定着させる目的では、数値だけを変更した類題も許容する。変更後も正答が一意になり、計算量・難易度・代表的な誤りが想定どおりかを改めて確認する。

## 3. 問題文の設計

### 3.1 条件を過不足なく書く

- 変数の範囲、定義域、全体集合を明示する
- 「異なる」「区別する」「重複を許す」などを明示する
- 単位・近似・端点を明示する
- 図からしか分からない条件を作らない
- 答えの形式と必要な精度を明示する

### 3.2 文脈は数学的な目的に従わせる

現実的な設定を加える場合でも、読解力や一般知識が過剰に影響しないようにする。文脈は数学的な構造を見えやすくするために使い、飾りとして増やさない。

### 3.3 複数の入口を許す

発展問題では、図、式変形、表、具体例、対称性、逆向きの考察など、複数の着手法があり得るようにする。ただし、基礎確認問題では狙いを一つに絞り、不要な迷いを生まない。

## 4. 誤答・選択肢・解説

### 4.1 誤答は原因まで設計する

誤答はランダムに作らず、実際に起こりやすい誤りから作る。

- 符号や不等号の向きを誤る
- 定義域・端点・全体集合を無視する
- 必要条件と十分条件を逆にする
- 順序を重複して数える、または数え落とす
- 途中式は正しいが、最後の条件確認をしない
- 図を正確な縮尺だと思い込む

選択肢は、正答の位置・長さ・表現だけで推測できないようにする。複数選択では、部分的な理解でも選べてしまわないかを確認する。

### 4.2 解説は「正解の理由」まで書く

解説には、少なくとも次を含める。

- 条件の整理
- 解法を選ぶ理由
- 主要な変形・判断
- 答えの確認
- 代表的な誤りと、その修正点

答えだけを出す問題でも、作問者側では途中過程と検算を残す。

## 5. 数学的な正確さと採点可能性

### 5.1 作問者が先に解答を完成させる

問題文を書く前に、正答、解法、別解、採点条件を用意する。次を確認する。

- 正答が存在する
- 正答が一意である、または許容する答えを明示できる
- 条件から解法が成立する
- 途中の式変形に飛躍がない
- 数値・符号・単位・定義域が整合している
- 特殊値、端点、境界条件を代入しても矛盾しない

### 5.2 採点基準を先に決める

記述式では、最終答だけでなく、どの段階に点を与えるかを決める。数値入力では、`prompts` と `answers` の対応を崩さない。選択式では、正答番号と選択肢の意味を独立に確認する。

## 6. 公平性・可読性

- 数学力と無関係な長文読解を必要以上に要求しない
- 固有の生活経験や文化知識を前提にしない
- 色や細かい図の見分けだけに依存しない
- 数式・図・選択肢の表示が崩れないことを確認する
- 問題文と解答欄の対応を明確にする

問題の難しさと、表示・読解上の負荷を分けて考える。難問にしたいからといって、説明を曖昧にしてはいけない。

## 7. `math-practice` 固有の作成ルール

### 7.1 ミニ試験は対応表を先に作る

ミニ試験の問題は、作成前に [`problem-source-map.md`](./problem-source-map.md) で参考資料、対応技能、変更方針を割り当てる。Web・参考資料の問題を利用するときは出典と利用条件を記録し、その範囲内で問題構造・問い方・設定を利用する。

変更対象は次の5項目から選ぶ。反復練習を目的とする場合は、数値だけの変更でもよい。

- 設定
- 式構造
- 問い方
- 条件
- 数値

### 7.2 ミニ試験の構成を守る

- 1回12問
- 合計100点
- 想定時間30分
- 単元ごとの配点と小問配点が一致する
- `numeric` は `prompts` と `answers` の個数が一致する
- すべての問題に `id`、`stem`、`solution` がある

### 7.3 公開範囲を管理する

参考PDF、抽出画像、教材本文などの原資料は、問題作成に使っても git や GitHub Pages に含めない。公開用データには、独自に作成した問題と必要な解説だけを置く。

## 8. 採用前の品質チェック（8項目）

各問題について、次をすべて確認する。

1. **目的との一致**：測りたい力が一文で説明できる
2. **出典・変更管理**：参考問題の出典、利用条件、変更した数値が記録されている
3. **数学的正確さ**：正答・解法・検算に誤りがない
4. **条件の十分性**：必要条件がそろい、答えが曖昧でない
5. **難易度の妥当性**：計算量だけでなく、判断・表現・時間を確認している
6. **誤答の診断性**：代表的な誤りと原因を説明できる
7. **表現・公平性**：不要な読解負荷や表示上の障害がない
8. **採点・解説の整合**：正答条件、配点、解説が問題文と一致している

問題を採用する前に、作問者以外の視点でも読み、可能なら生徒に試す。実施後は正答率、所要時間、無解答、誤答類型を記録し、必要なら修正する。

