## 前提

- 移植元は `prints/rikaido2507/I.tex`。**この `.tex` は読むだけで、変更も削除もしない。**
- 内容（方針の文面、解答、図の座標）は3回のレビューで検証済み。**書き直さず、そのまま移す。**
  表現を「改善」しようとしないこと。
- アプリは既にKaTeXを読み込んでいる。

## 手順

### 1. `static/rikaido2507-solutions.js` を新規作成

`I.tex` の `approqwari`（方針）と `multicols*` 内の解答から、【I】の5小問を移す。

```js
window.MATH_SOLUTIONS = window.MATH_SOLUTIONS || {};
window.MATH_SOLUTIONS.rikaido_2507_beta = {
  "1-(1)": {
    approach: "…",                                   // 方針。敬体のまま
    formula: { title: "対称式の基本変形", body: "…" }, // fmlqwari。無い小問は省略可
    solution: "…",                                   // 解答。論理展開
    answer: "…",                                     // 最終的な答えだけ
  },
  // 1-(2) … 1-(5)
};
```

キーは既存の `detailKey(group, sub)` と同形（`"1-(1)"`）。
`figure` フィールドは手順5で足す。

**変換は次の2点だけ。**それ以外の本文は1文字も変えない。

- `\begin{align*}…\end{align*}` → `$$\begin{aligned}…\end{aligned}$$`
- `\hspace{\zw}$\cdots $\textgt{(答)}` は削除し、その行の答えを `answer` フィールドへ移す

`\bun`・`\leqq`・`\text{}`・`\vec{}`・`\triangle`・`\Longleftrightarrow` はそのままでよい。

index.html の `rikaido2507-data.js` の後に script タグを1行足す。

### 2. `renderMath()` に KaTeX マクロを足す

`\bun` を `.tex` と同じ意味で使えるようにする。

```js
macros: { "\bun": "\dfrac{#1}{#2}" }
```

**既存の `delimiters` と `throwOnError` は変えない。**

### 3. 小問カードに「方針を見る」を実装

`renderSubCard`（`sub-checkbar` のある関数）に足す。

- **常時表示する。**`#hideSolutions` の対象外にする。方針は答えを含まないため。
  既存の `canShowSolution` の判定に混ぜないこと。
- 押すと、その小問の `approach` と `formula` **だけ**を表示する。
  **`solution` と `answer` は絶対に出さない。**
- モーダルではなく**カード内で開閉**する。解いている手を止めさせないため。
- `aria-expanded` で開閉状態を伝える。操作領域は44px以上（`DESIGN.md`）。
- `MATH_SOLUTIONS` にその小問が無いデータセットではボタンを出さない。

### 4. 解説モーダルを 問題 / 方針 / 解答 に変える

`renderSolutionModalBody()` を書き換える。

- `MATH_SOLUTIONS` にデータがある場合：**問題 / 方針 / 解答** の3セクション。
  `answer` は解答セクションの末尾に置く。
- 無い場合：現行のまま（問題 / 答え / 解説ステップ）。**1文字も変えない。**
- **現在のPDFリンク（`printUrlFor`）は使わなくなる。**ただし `static/print-sources.js` と
  `static/prints/` は **Phase 3 まで残す**。消さないこと。

### 5. 【I】の図をSVG化

`I.tex` の TikZ を SVG に移す。座標は検証済みなので**変更しない**。

| 点 | 座標 |
|---|---|
| $B$ | $(0,\ 0)$ |
| $C$ | $(7,\ 0)$ |
| $A$ | $(38/7,\ 8\sqrt5/7) = (5.4286,\ 2.5560)$ |
| $D$ | $(14/3,\ 0) = (4.6667,\ 0)$ |
| $I$ | $(5,\ \sqrt5/2) = (5,\ 1.1180)$ |

- SVGのy軸は下向きなので反転させる。
- 線と文字は `currentColor` で描き、ライト・ダーク両テーマで読めるようにする。
- 図中の注記は `$BD:DC=2:1$` の1つだけ。**長さや比の値を図に書き込まない**（本文にある）。
- ラベルが線分・他のラベルと重ならないよう配置する。
  **拡大では重なりは解消しない。ラベルの位置を動かすこと。**
- この図は `1-(5)` の `solution` に属する。**方針側には出さない。**

### 6. `scripts/check-solution-modal.js` を更新

見出しの契約を検証しているので、書き換える。

- `MATH_SOLUTIONS` あり：`["問題","方針","解答"]`
- なし：`["問題","答え","解説"]`（現行の契約を維持）

# Phase 1 修正（2026-08-19 レビュー）

仕組みは設計通り動いている。**方針に答えが出ていないことは5小問すべてで確認済み**、
KaTeXのレンダーエラー0件、未移行データセットへの影響なし。
以下の3件を直せば Phase 2 に進める。

## 1.【必須】【I】(5) のSVG図の縦横比が歪んでいる

**場所**：`static/rikaido2507-solutions.js` の `"1-(5)"` の `figure`

**現状**：x方向は32px/単位だが、**y方向が40px/単位**になっている。
そのため三角形の形が、与えられた辺の長さと一致していない。

| 辺 | 図での長さ | 真値 |
|---|---|---|
| $AB$ | 6.31 | 6 |
| $BC$ | 7.000 | 7 |
| $CA$ | 3.56 | 3 |

$CA$ が18%長い。内心の位置関係も視覚的に正しくなくなる。
**座標そのものは `.tex` の値が正しく使われている。スケールだけの問題である。**

**修正**：y方向もx方向と同じ倍率にする。32px/単位を保つ場合、点は次になる。

| 点 | 現在 | 修正後 |
|---|---|---|
| $A$ | (214, 27.76) | **(213.71, 48.22)** |
| $B$ | (40, 130) | 変更なし |
| $C$ | (264, 130) | 変更なし |
| $D$ | (189.33, 130) | 変更なし |
| $I$ | (200, 85.28) | **(200, 94.22)** |

ラベルの位置も追随させる。図の上下に不要な余白が残らないよう `viewBox` を調整する。

**完了条件**：SVGの点から計算した辺の比が **$AB:BC:CA = 6:7:3$ に対して誤差1%以内**であること。
DOMから `circle` の座標を読んで検算すること。

## 2.【必須】答えが2回表示される

**場所**：`static/rikaido2507-solutions.js` の5小問すべて

**現状**：`solution` の末尾が「よって $AI:ID=9:7$ である。」で終わり、
その直後にモーダルが「答え：$AI:ID=9:7$」を出している。

**原因**：本書の手順1で「`(答)` 記法を削除して `answer` へ移す」とだけ指示したため、
**結語の文が `solution` に残ったまま `answer` が追加された。**指示が曖昧だった。

**修正**：`solution` 末尾の結語（「よって〜である。」の1文）を削り、`answer` に一本化する。
5小問すべてで行う。`answer` フィールドの中身は変えない。

## 3.【必須】`app.js` のキャッシュバスターが未更新

**場所**：`index.html`

`?v=20260819-print-migration` のままになっている。`app.js` は大きく変わったので、
このままデプロイすると**生徒のブラウザに古いJSが残る**。
`?v=20260819-hint-html` などに更新する。

## 保留（今は変更しない）

- 【I】(4) の方針にある「そのため最終的な確率は同じになるはずです」は、
  **2026-08-19 にユーザーが「このままでよい」と判断済み。変更しないこと。**
  方針は「なぜその解法を選ぶか」を伝えるものであり、対称性への気づきを促すのは役割の範囲内で、
  値そのものは伏せられているため。同種の表現を他の大問で削らないこと。
- SVGのラベル（A/B/C/D/I）の書体が本文の数式（KaTeXの斜体）と異なる。体裁のみ。
- ダークテーマはアプリに未実装（`prefers-color-scheme` の指定が0件）。
  `currentColor` の使用は正しいので、将来対応したときに効く。今は確認できない。
